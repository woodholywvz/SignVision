# SignVision MVP

Сайт для распознавания заранее заданных фраз РЖЯ по короткой видеозаписи. OpenCV декодирует видео; MediaPipe Tasks извлекает 21 точку каждой руки и 33 точки тела. Для каждого кадра сохраняются положение рук относительно плеч, форма кисти относительно запястья и координаты верхней части тела. DTW сравнивает последовательности с учётом траектории и скорости, kNN выбирает фразу. Запись с маленькой долей кадров с руками, далёкая от всех примеров или неоднозначная запись получает ответ «Неизвестный жест».

## Запуск

Нужен Python 3.11–3.13. Из корня проекта:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m signvision.models
uvicorn signvision.web:app --reload
```

Откройте [http://localhost:8000](http://localhost:8000). Браузеру нужен доступ к камере. Сайт записывает жест через `MediaRecorder` и отправляет видео серверу. Также можно загружать готовые MP4/WebM/MOV/AVI. После обработки видео удаляется; в `data/` сохраняются только ключевые точки в `.npz`. Фразы и пороги задаются в `config.yaml`; после их изменения перезапустите сервер. Ошибки записываются в `logs/errors.log`.

Интерфейс доступен на русском и английском: переключатель RU/EN находится в шапке, выбор сохраняется в браузере и в параметре `?lang=ru` или `?lang=en`. Русская форма фразы задаётся полем `text`, английский перевод — необязательным полем `en` в `config.yaml`. Если перевода нет, показывается русский текст. API локализует результат и ошибки по заголовку `Accept-Language` (`ru` или `en`).

## Проверка суставов в реальном времени

На вкладке «Распознавание» нажмите **«Проверить суставы»** над изображением камеры и разрешите доступ в браузере. Датасет для этой проверки не нужен. Зелёные точки и линии показывают кисти, синие — суставы тела; точки с низкой уверенностью модели скрываются. Нажмите «Скрыть суставы», чтобы остановить отслеживание, или «Выключить», чтобы выключить камеру. При переходе в другую вкладку сайта камера выключается автоматически.

Браузер передаёт JPEG-кадры в `/api/track` по WebSocket; сервер использует OpenCV и MediaPipe Tasks. На каждое соединение создаётся отдельный трекер, который освобождается при отключении. Следующий кадр отправляется только после ответа на предыдущий: целевая частота — до 10 кадров/с, фактическая зависит от компьютера. Кадры проверки не записываются на диск и не добавляются в датасет. Видеозаписи распознавания и проверка суставов используют общий модуль `signvision/tracking.py`.

Начните с нескольких записей каждой фразы от разных людей. Выберите фразу перед сохранением записи. Блок проверки принимает отдельные, ещё не добавленные в датасет видео и показывает точность по всем загруженным файлам. Можно добавить метку «Неизвестный жест» для проверки отказа от неизвестного класса. Эти тестовые записи не сохраняются в обучающий датасет. Для реальной оценки держите людей и условия съёмки независимыми от обучающих примеров.

Список фраз в поставке служит конфигурацией интерфейса, а не готовой обученной моделью. Порог `max_distance` и `min_margin` нужно откалибровать на своих независимых видео. Прототип принимает один жест на запись и не переводит непрерывную речь.

## Тесты

```powershell
pytest -q
node --test tests/tracking.test.cjs
```

Тесты WebSocket проверяют повторное использование трекера, освобождение моделей, отсутствие рук и ошибки кадров. Тесты клиента проверяют очистку точек и отмену запоздалых кадров после остановки и повторного запуска. Node.js нужен только для клиентских тестов.

Модели скачиваются из [официального хранилища MediaPipe](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/python) при выполнении `python -m signvision.models` и остаются в игнорируемой Git папке `models/`.

## Версия для ChatGPT Sites

Папка `site/` содержит размещаемую версию того же интерфейса. Браузер использует MediaPipe Tasks Vision для извлечения точек из камеры и загруженных видео; для распознавания на Sites передаются только нормализованные последовательности. Эталоны хранятся в R2, а Worker выполняет DTW + kNN и оценку независимых записей. Добавление видео сразу меняет набор примеров для сравнения; нейросеть при этом не дообучается. Пустые кадры по краям видео удаляются. Видео эталона должно содержать один жест и длиться не более 8 секунд. Живой перевод подбирает окно сравнения по длительности эталона. Пять исходных фраз и пороги заданы в `site/config.json`; администратор может добавить до 30 новых фраз в разделе «Эталонные жесты». Новые фразы хранятся в D1 и сразу появляются в уроках, распознавании и проверке точности. Для каждой фразы можно загрузить до 25 эталонов, всего до 300. Исходные видео эталонов в облаке не сохраняются. Для первого запуска нужна сеть, чтобы браузер загрузил библиотеку и модели MediaPipe.

На опубликованном сайте вход выполняется через ChatGPT. После входа посетитель создаёт профиль SignVision. Пока профилей нет, первым зарегистрироваться может только владелец сайта с подтверждённым адресом из `BOOTSTRAP_ADMIN_EMAIL`; его профиль становится администраторским. Затем он может назначать других администраторов. Только администраторы загружают и удаляют эталоны, редактируют инструкции уроков и добавляют учебные MP4/WebM до 20 МБ. Учебные видео сохраняются в R2 и доступны для просмотра в уроках. Пользовательский прогресс хранится в D1 отдельно для каждого профиля; урок засчитывается после распознавания нужной фразы в записи с камеры. Тёмная тема хранится как предпочтение браузера. Структура D1 — в `db/schema.ts`, миграции — в `drizzle/`.

Автоматические тесты проверяют прохождение эталона через сохранение и распознавание, независимый вариант с другой длиной и небольшим шумом, отказ для далёкого жеста и отсутствие смещения к фразе с большим числом эталонов. Точность на настоящем РЖЯ пока не измерена: для неё нужны загруженные пользователем эталоны и отдельные видео для проверки. После загрузки откройте «Проверка точности» и подбирайте `max_distance`, `tentative_distance` и `min_margin` по этим результатам.

Перед локальной проверкой Worker выполните `npm install`, `node site/build.mjs`, затем `npm test`. Тесты Site используют временную SQLite-базу и не изменяют опубликованный сайт. Версия Python с OpenCV остаётся доступной для локальной обработки видео.
