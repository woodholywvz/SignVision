# SignVision

SignVision — прототип для изучения и распознавания **фиксированных фраз русского жестового языка (РЖЯ)**. Пользователь записывает короткий жест, приложение извлекает ключевые точки рук и тела и сравнивает их с эталонами методом DTW + kNN. При достаточном сходстве оно показывает фразу; при сомнительном — возможный вариант и совет; далёкий жест оставляет неизвестным.

**Статус:** MVP. MediaPipe извлекает точки, но не обучается на загруженных примерах. Добавление эталона меняет набор для сравнения, а не веса нейросети. Точность на реальном РЖЯ не установлена: для её измерения нужны независимые записи от других людей и из других условий съёмки. Приложение работает с одним жестом в короткой записи, а не переводит непрерывную речь.

## Возможности

- Отслеживание суставов рук и верхней части тела поверх изображения камеры в реальном времени. Точки можно включить или скрыть **во время записи**.
- Интерактивная запись эталонов с камеры и загрузка коротких видео. Для каждого примера сохраняется последовательность нормализованных ключевых точек.
- Распознавание записи и режим живого перевода. Сайт отклоняет далёкие жесты и показывает осторожную подсказку для пограничных совпадений.
- Независимая проверка точности на отдельных видео, включая метку «Неизвестный жест».
- Уроки с инструкциями, учебными видео, практикой и личным прогрессом.
- Профили, вход через ChatGPT или по почте с паролем, роли ученика и администратора. Администратор видит пользователей и их прогресс, назначает роли и управляет учебными материалами.
- Русский и английский интерфейс; светлая и тёмная темы.

## Как устроено распознавание

```text
Камера / видео → MediaPipe (21 точка на каждую кисть, 33 точки тела)
               → нормализация и маски отсутствующих рук
               → последовательность признаков
               → DTW: расстояние до каждого эталона
               → kNN: сравнение кандидатов по фразам
               → фраза / возможная фраза / неизвестный жест
```

Вектор кадра содержит 284 значения: признаки обеих рук, точки верхней части тела и положение запястий. Координаты кистей рассчитываются относительно плеч и размера тела, форма пальцев — относительно запястья и ладони. Если тело не найдено, используется опора на видимые руки. Отсутствующая рука имеет отдельную маску; при изменении длины записи её точки не должны появляться из-за интерполяции. Последовательности приводятся к сопоставимой длине. DTW учитывает форму траектории и изменение положения между кадрами.

`max_distance` ограничивает расстояние до известной фразы, `min_margin` требует отрыва от следующего кандидата. Для почти точного совпадения (расстояние ≤ 0,03) дополнительно учитывается относительный отрыв: одинаковые эталоны с разными метками всё равно считаются неоднозначными. `tentative_distance` задаёт зону осторожной подсказки как для записи, так и для живого режима. **Расстояние DTW не является вероятностью или процентом точности.** Эти пороги следует подбирать на независимых видео, а не на эталонах, с которыми сравнивается жест.

Живой режим проверяет окна длительностью 75%, 100% и 125% от длительности эталона и допускает паузу около 0,3 секунды после жеста. Сравнение уменьшает вес шумной глубины `z` и учитывает полное перемещение каждого запястья, чтобы частичный или обратный ход не совпадал только по отдельным позам. Формат старых эталонов сохраняется.

При сомнении карточка показывает возможную фразу, а при близких конкурирующих вариантах — обе фразы. Нераспознанный жест также получает совет. Подсказки используют видимость рук и плеч, яркость кадра, обрезку кистей у края, направление и скорость относительно ближайшего эталона. Для далёкого жеста приложение предлагает посмотреть пример и повторить фразу целиком, без предположений о значении. Это эвристики, а не экспертная оценка правильности РЖЯ.

Если «Привет» и «До свидания» записаны одинаковым движением, текущие признаки не смогут надёжно различить их. Проверьте метки и разные исполнения эталонов этих фраз; качество на реальных пользователях измеряйте через оценку на независимых видеозаписях. Синтетические регрессионные тесты проверяют механику классификатора, но не подтверждают точность перевода РЖЯ.

## Две версии приложения

| Компонент | Локальная версия | Публичная версия ChatGPT Sites |
| --- | --- | --- |
| Интерфейс | `static/` | `site/`, `static/style.css`, `static/ui-refresh.css` |

Эти версии **не разделяют датасет**. Запись, добавленная на локальный сервер, не появляется на публичном сайте. Исходные видео эталонов не хранятся в R2: браузер отправляет нормализованные точки. Учебные видео уроков, в отличие от эталонов, сохраняются в R2.

## Локальный запуск: Python

Проверенная среда — Python 3.11–3.13. Нужны веб-камера, браузер с `MediaRecorder` и доступ к сети для первой загрузки моделей MediaPipe.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m signvision.models
uvicorn signvision.web:app --reload
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) и разрешите доступ к камере. Выберите фразу, запишите жест и добавьте эталон. Вместо записи можно загрузить MP4, WebM, MOV или AVI с поддерживаемым кодеком. Для отслеживания без записи нажмите «Проверить суставы». Зелёные точки обозначают кисти, синие — тело. Кадры этой проверки в датасет не попадают.

Файлы видео обрабатываются временно и удаляются после извлечения признаков. Эталоны остаются в `data/`, ошибки — в `logs/errors.log`; обе папки исключены из Git. [`config.yaml`](config.yaml) задаёт пять исходных фраз, частоту выборки, длину записи, лимит загрузки и пороги. После изменения конфигурации перезапустите сервер. Поле `en` — необязательный английский перевод; без него используется русский текст.

Для разработки локальной версии установите также инструменты проверки:

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check signvision tests
python -m ruff format --check signvision tests
```

## Разработка версии ChatGPT Sites

Для сборки и тестов нужен Node.js с `node:sqlite` и Web Crypto; проект проверен на Node.js 24. Нужен Python из предыдущего раздела, если запускаете полный набор проверок.

```powershell
npm ci
npm run build
npm test
```

`npm run build` собирает Worker в `dist/server/index.js`, встраивает статические ресурсы и копирует [`drizzle/`](drizzle/) с миграциями D1. `npm test` запускает тесты на временной SQLite-базе и подменяемом R2; **опубликованные данные не изменяются**. Отдельного `npm run dev` для версии Sites сейчас нет. Публичный Worker публикуется через ChatGPT Sites из этого же проекта.

Основные файлы:

| Путь | Назначение |
| --- | --- |
| `site/tracking.js` | MediaPipe в браузере, признаки записи и наложение суставов |
| `site/app.js` | Камера, запись, живой перевод и работа с датасетом в интерфейсе |
| `site/learning.js` | Профили, уроки, администрирование и прогресс в интерфейсе |
| `site/worker.js` | HTTP API, DTW + kNN, работа с эталонами |
| `site/accounts.js`, `site/email-auth.js` | Права доступа, вход и сессии |
| `site/lessons.js`, `site/phrases.js` | Уроки и каталог фраз |
| `site/i18n.js` | Русские и английские строки интерфейса |
| `db/schema.ts`, `drizzle/` | Схема D1 и последовательные миграции |
| `tests/` | Проверки обработки, распознавания, прав и API |

Исходные пять фраз и пороги Sites задаются в [`site/config.json`](site/config.json). Администратор может добавить до 30 фраз через интерфейс; они сохраняются в D1 и сразу появляются в словаре, уроках и распознавании. Изменение `config.yaml` не влияет на Sites. При добавлении нового текста интерфейса обновляйте оба языка в `site/i18n.js`.

## Аккаунты, роли и данные

Первый профиль создаёт владелец, вошедший через ChatGPT с адресом `BOOTSTRAP_ADMIN_EMAIL`. Он получает роль администратора. После этого открывается регистрация по почте: новый профиль получает роль ученика. Пользователь ChatGPT может добавить пароль **к своему существующему профилю**, чтобы оба способа входа использовали тот же прогресс. Повторная регистрация с занятым адресом не создаёт второй профиль. Администратор назначает другие роли в списке пользователей; последнего администратора нельзя разжаловать.

Пароль хранится в D1 как PBKDF2-SHA256 с индивидуальной случайной солью и 210 000 итераций. Для значений выше лимита Web Crypto в Cloudflare Workers (100 000) используется совместимая реализация `@noble/hashes`, включённая в серверную сборку через esbuild. Существующие хеши и пароли сохраняются; тест имитирует производственный лимит и проверяет вход по хешу, созданному Node.js. Токен почтовой сессии хранится только в виде хеша; cookie имеет `HttpOnly`, `Secure`, `SameSite=Lax` и действует 30 дней. После пяти неудачных попыток вход блокируется на 15 минут. **Подтверждения адреса и восстановления пароля пока нет.** Пользователям нужно сохранить пароль; владельцу стоит сохранить возможность входа через ChatGPT.

Форма входа открывается до загрузки уроков и списка эталонов. После успешной авторизации профиль отображается сразу, а уроки и данные управления загружаются отдельно. Вход через ChatGPT возвращает пользователя в раздел профиля.

Успешная регистрация, вход и завершение практики урока сопровождаются короткими звуковыми сигналами. Кнопка с нотой в шапке отключает звуки; выбор сохраняется в браузере. Сигналы создаются локально через Web Audio без загрузки аудиофайлов. После перенаправления из ChatGPT звук входа может воспроизвестись при следующем взаимодействии со страницей из-за ограничений автозапуска браузера. Обычное открытие сайта не воспроизводит звук входа.

| Данные | Где находятся | Кто меняет |
| --- | --- | --- |
| Эталоны: точки, фраза, автор и время загрузки | R2, `samples/…` | Администратор |
| Учебные видео | R2 | Администратор |
| Профили, роли, почтовые реквизиты и сессии | D1 | Пользователь и API аккаунтов |
| Дополнительные фразы, материалы и прогресс уроков | D1 | Администратор; прогресс — сам ученик |
| Локальные эталоны `.npz` | `data/` на компьютере | Локальный сервер |

Старые эталоны сохраняются при обновлении кода и смене домена. Если пример был загружен до появления учёта автора, имя автора останется неизвестным. Миграция `0002` добавляет таблицы входа по почте и не удаляет существующие профили, прогресс или примеры. Для рабочей среды важно хранить резервные копии D1 и R2 средствами платформы перед изменениями схемы или массовым удалением данных.

## Сбор эталонов и оценка

1. Для каждой фразы соберите несколько коротких записей **одного жеста** от разных людей. Меняйте ракурс и освещение, но держите кисти и плечи видимыми.
2. В Sites запись эталона должна длиться не более 8 секунд. Для одной фразы доступно до 25 эталонов, всего — до 300. Исходные видео эталонов после извлечения точек не сохраняются.
3. Отложите отдельные видео для оценки: не используйте кадры одной записи одновременно как эталон и как проверку. По возможности отделите участников съёмки и условия.
4. В разделе «Проверка точности» загрузите отложенные видео с правильными метками. Добавьте чужие жесты с меткой «Неизвестный жест», чтобы оценить отказ от неподходящих фраз.
5. Смотрите ошибки по каждому видео и только затем подбирайте пороги. Показатель на тренировочных эталонах завышает ожидаемое качество.

Тестовые видео не добавляются в обучающий датасет. В режиме живого перевода сравнивается скользящее окно движения; явные промахи не озвучиваются как фраза. Советы при пограничном совпадении основаны на признаках записи и не гарантируют верную классификацию.

## API и структура проекта

Ключевые маршруты версии Sites (JSON, если не указано иное):

| Маршрут | Действие |
| --- | --- |
| `GET /api/config`, `GET /api/lessons` | Каталог, число эталонов, уроки |
| `GET /api/me` | Состояние входа и профиль текущего пользователя |
| `POST /api/email/register`, `/login`, `/logout`, `/link` | Регистрация, вход, выход и добавление пароля к профилю ChatGPT |
| `POST /api/recognize`, `POST /api/live` | Распознавание последовательности точек |
| `POST /api/evaluate` | Оценка отдельных размеченных записей |
| `POST /api/lessons/{id}/start`, `/practice` | Начало урока и проверка практики |
| `POST /api/samples` | Добавление эталона администратором |
| `GET /api/admin/users`, `POST /api/admin/users/{id}/role` | Просмотр прогресса и изменение ролей |
| `GET /api/admin/samples`, `DELETE /api/admin/samples/{id}` | Просмотр автора/даты и удаление выбранного эталона |
| `POST /api/admin/phrases`, `POST /api/admin/lessons/{id}` | Новые фразы и материалы уроков |

Локальная Python-версия принимает **видеофайлы**, а Sites API — **последовательности ключевых точек**. Поэтому эти API не взаимозаменяемы. Реализацию и форматы ответов смотрите в [`signvision/web.py`](signvision/web.py) и [`site/worker.js`](site/worker.js).

## Проверки и стиль кода

После установки `npm ci` и `requirements-dev.txt` запустите весь набор:

```powershell
npm run check
```

Он проверяет форматирование Prettier, правила ESLint, Ruff для Python, 15 тестов Sites, 3 теста клиентского отслеживания и 16 Python-тестов. Отдельные команды: `npm run format:check`, `npm run lint:js`, `npm run lint:python`, `npm test`, `python -m pytest -q`. Для автоматического форматирования: `npm run format` и `python -m ruff format signvision tests`.

Правила хранятся в [`.editorconfig`](.editorconfig), [`.prettierrc.json`](.prettierrc.json), [`eslint.config.mjs`](eslint.config.mjs) и [`pyproject.toml`](pyproject.toml). Python проверяется на ошибки, импорты и типичные дефекты. В JavaScript обязательны фигурные скобки для управляющих блоков, строгие сравнения и отсутствие `eval`. Скрипты браузера и Worker объединяются в заданном порядке при сборке, поэтому ESLint не проверяет неопределённые глобальные имена **между** этими файлами; поведение покрывается тестами сборки и API. Новые модули лучше делать небольшими и с явными контрактами.

## Публикация и собственный домен

Файл [`.openai/hosting.json`](.openai/hosting.json) привязывает исходники к существующему проекту ChatGPT Sites и его D1/R2. Обновление сайта выполняется так: проверить код → собрать `dist/` → отправить точный коммит в исходный Git-репозиторий Sites → сохранить версию из этого коммита и сборки → опубликовать сохранённую версию → проверить статус и основные маршруты. Миграции из `dist/.openai/drizzle/` должны примениться до использования новых таблиц. Не создавайте другой проект Sites для обычного обновления или смены домена: это дало бы пустые хранилища.

Собственный домен добавляется к **тому же проекту**. Значения A/TXT или CNAME и записи подтверждения берите из настроек домена Sites; для корневого домена используйте выданные A-записи. После сохранения DNS дождитесь подтверждения домена и сертификата. Браузерные cookie привязаны к имени хоста, поэтому после смены адреса пользователю может понадобиться снова войти. Профили, уроки и эталоны при этом остаются в тех же D1/R2. Пока новый домен не подтверждён, старый адрес продолжает работать.

## Диагностика и ограничения

| Симптом | Что проверить |
| --- | --- |
| Камера не включается | Разрешение браузера, HTTPS или `localhost`, занятость камеры другой программой |
| Суставы не видны | Руки целиком в кадре, освещение, доступность моделей MediaPipe, сообщение под камерой |
| Жест остаётся неизвестным | Число и разнообразие эталонов, видимость рук, движение, пороги и отдельные тестовые видео |
| Нет урока или прогресса | Публикацию материала администратором, вход в профиль, успешное распознавание нужной фразы |
| Не работает вход по почте | Длина пароля 12–128 символов, временная блокировка после пяти ошибок, миграция D1 `0002` |
| После смены домена нет сессии | Повторный вход на новом адресе; данные профиля остаются в D1 |
| Домен не открывается | Статус домена и SSL в Sites, фактически сохранённые DNS-записи и их распространение |

Распознавание ограничено набором фиксированных фраз. Частично закрытые кисти, плохой свет, сильный поворот тела и непривычный стиль исполнения снижают качество. Не применяйте этот MVP как единственный способ общения в ситуациях, где ошибка перевода может причинить вред.

Модели локальной версии загружаются из [официального хранилища MediaPipe](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/python) командой `python -m signvision.models` в игнорируемую Git папку `models/`. Версия Sites получает библиотеку и модели через маршруты `/mediapipe/`, которым для первой загрузки нужна сеть.
